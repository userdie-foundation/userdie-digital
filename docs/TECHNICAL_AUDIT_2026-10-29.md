## Backend: фактическая граница реализации

В `backend/src/index.mjs` и `backend/src/server.mjs` обнаружен базовый Node.js API-каркас с PostgreSQL pool и корректным завершением процесса. Реализованы:
- `GET /api/v1/health/live` — проверка жизнеспособности процесса;
- `GET /api/v1/health/ready` — проверка доступности базы данных;
- `GET /api/v1/applications` — намеренно возвращает `503 applications_module_unavailable`, пока не реализованы аутентификация и проверка прав на уровне записей;
- неизвестные маршруты возвращают 404, методы кроме GET/HEAD — 405.

В коде присутствуют базовые заголовки безопасности: `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Cache-Control: no-store` и ограничивающий Content Security Policy. Тесты для API находятся в `backend/test/server.test.mjs`; workflow `.github/workflows/backend-checks.yml` запускает проверку синтаксиса и `npm test`.

**Вывод:** backend — начальный каркас, а не готовая система приёма обращений. Не подключать реальные заявления, документы, персональные данные или пользовательские учётные записи до реализации и тестирования аутентификации, ролей, авторизации на уровне записей, аудита, защищённой загрузки файлов, резервного копирования и восстановления.

## Что пока не подтверждено

- Независимая доступность пользовательского домена и GitHub Pages в браузере на момент проверки: инструментальная попытка открыть адреса завершилась ошибкой; сетевой DNS-запрос из рабочей среды также не разрешил имена. Это не доказывает, что сайт недоступен для всех пользователей, но не позволяет подтвердить доступность.
- Что последняя правка CSS уже отображается на опубликованном сайте.
- Полная визуальная приёмка на физическом мобильном устройстве и широком экране.
- Полный аудит безопасности и защита от DDoS. Успешный CodeQL и сканирование шаблонов секретов не равны комплексному аудиту.
