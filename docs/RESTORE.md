# Восстановление репозитория «Усердие»

## Что делает резервная копия

Скрипт `scripts/backup-repository.sh` создаёт или обновляет зеркальную Git-копию со всей доступной историей и ссылками Git. Это резервная копия **исходного кода**, а не резервная копия настроек GitHub Pages, DNS REG.RU, секретов GitHub Actions или данных заявителей.

## Создание копии

1. Установить Git на компьютере.
2. Подключить отдельный диск или выбрать другое независимое хранилище. Не сохранять копию только внутри папки исходного проекта.
3. Из корня клонированного репозитория выполнить:

   ```bash
   bash scripts/backup-repository.sh /путь/на/отдельном/диске/userdie-digital.git
   ```

4. Дождаться сообщения `Backup mirror verified`. Скрипт запускает `git fsck --full`; ненулевой код означает, что проверка не пройдена.
5. Для независимости хранить диск/копию отдельно от основной учётной записи GitHub. Повторять после значимых изменений и по принятому графику.

## Восстановление в рабочую папку

Из проверенной зеркальной копии:

```bash
git clone /путь/к/userdie-digital.git userdie-digital-restored
cd userdie-digital-restored
git checkout main
```

Если ветка `main` не появилась автоматически, посмотреть доступные ветки командой `git branch -a` и выбрать существующую ветку.

## Восстановление публикации сайта

1. Открыть восстановленную папку и проверить `website/` и `.github/workflows/deploy-website.yml`.
2. Запустить локальную проверку файлов и ссылок; отдельно проверить главную страницу, `prototype/platform.html`, `prototype/applicant-cabinet.html` и `404.html`.
3. Для публикации через GitHub Pages потребуется доступ к GitHub-аккаунту и корректные настройки Pages/workflow. Зеркальная копия сама по себе не переносит настройки Pages, домен, DNS, secrets или environment.
4. Не менять DNS REG.RU без отдельной проверки домена и согласованного плана переключения.

## Статус проверки

Добавление скрипта и инструкции не означает, что резервная копия уже создана или восстановление успешно испытано. Отмечать этап выполненным только после фактического запуска на отдельном носителе и проверки восстановления.
