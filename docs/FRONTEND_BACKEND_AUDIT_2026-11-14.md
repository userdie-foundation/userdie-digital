## 2. Публичный интерфейс

### Подтверждено в исходниках

- `website/index.html` содержит навигационные переходы к карте платформы, кабинету заявителя, партнёрскому пространству, рабочему пространству, офису, направлениям помощи и другим информационным разделам.
- `website/prototype/applicant-cabinet.html` явно обозначен как демонстрационный макет; реальная авторизация, серверное хранение и отправка обращений не подключены.
- `website/prototype/partner-space.html` явно обозначен как демонстрационный интерфейс без авторизации и обмена данными.
- `website/prototype/workspace.html` содержит интерактивные демонстрационные разделы и форму объекта; состояние демо-задач сохраняется локально в браузере, а не отправляется на сервер.
- В пользовательских уведомлениях присутствуют предупреждения не передавать персональные документы через демонстрационные интерфейсы.

### Вывод

Публичная информационная часть и интерактивные прототипы существуют. Нельзя представлять кабинеты и рабочее пространство как подключённые к реальной системе приёма обращений или совместной серверной работе.

## 3. Backend и API

### Реализовано в репозитории

- Node.js HTTP API и PostgreSQL connection pool.
- Миграции базы данных 001–014.
- Серверные сессии, разрешение principal из доверенного хранилища, scoped role grants и отзыв разрешений.
- Ограничение частоты попыток входа и восстановления на уровне account/network buckets.
- Read-only маршруты для программ, деталей программ, партнёрского каталога/деталей и внутренних workflow-данных.
- Узкий переход статуса задачи `PATCH /api/v1/workspace/tasks/:id/status` с проверкой полномочий и транзакционной записью события.
- Ограничение изменения/удаления audit events на уровне PostgreSQL triggers.
- Backend Dockerfile и CI-сборка/контейнерная smoke-проверка описаны в runbook.

### Ограничения, подтверждённые исходниками

- В `backend/src/index.mjs` сервис аутентификации создаётся только при наличии `LOGIN_RATE_LIMIT_HMAC_KEY`; это условная wiring-логика, не свидетельство развернутого сервиса.
- Recovery rate limiter может быть создан из конфигурации, но runtime entry point не создаёт и не передаёт `recoveryService`; доверенный почтовый delivery adapter не настроен. Восстановление доступа не готово к эксплуатации.
- MFA migration 012 — основа хранения; KMS/HSM, enrolment, verification, challenge consumption и enforcement не реализованы.
- Коллекция обращений намеренно возвращает недоступность; публичный intake и полноценные write APIs для обращений не готовы.
- Партнёрские маршруты read-only; загрузка/скачивание документов, операции изменения партнёрств и публичная публикация партнёрского каталога не готовы.
- Рабочий интерфейс не подключён к API; подтверждённого production/staging API host нет.
- Не подтверждены реальные резервные копии и restore drill, мониторинг, оповещения и эксплуатационный владелец.

## 4. Релизные ограничения

До подключения публичного интерфейса к API требуются:

1. Утверждение hosting provider/region и бюджета staging.
2. Изолированная пустая PostgreSQL staging database с TLS.
3. Раздельные migration-owner и least-privilege runtime роли.
4. Защищённое хранение секретов и конфигурации.
5. Контролируемое применение миграций 001–014 к новой пустой staging базе и подтверждение integration tests.
6. Утверждение почтового провайдера и реализация recovery delivery.
7. Решение по KMS/HSM и реализации/обязательности MFA для привилегированных ролей.
8. Privacy/security review, backup/restore rehearsal, monitoring, incident/rollback plan.
9. E2E-тестирование на синтетических данных и отдельная приёмка доступа к каждой записи.
10. Только после этого — развёртывание API, TLS/CORS-проверка и подключение UI.

Никакие DNS/MX изменения, платные ресурсы или подключения к реальным персональным данным этим аудитом не выполнялись.
