USERDIE DIGITAL · АРХИТЕКТУРА И ИНЖИНИРИНГ

Технический контракт.
Данные, права и контроль.

Базовые правила будущей серверной системы фонда: какие сущности существуют, как разделяются контуры, кто вправе выполнять операции и какие события должны оставлять проверяемый след.

Проект архитектурных требований Не является действующей базой данных или API

01 / НЕИЗМЕНЯЕМЫЕ ГРАНИЦЫ

Сначала — безопасная архитектура.

Контракт задаёт ограничения для проектирования backend, интерфейсов, интеграций и автоматизированных помощников.

ОРГАНИЗАЦИОННАЯ МОДЕЛЬ

Три функциональных контура

  • Фонд «УСЕРДИЕ» — основная организация и владелец процессов.
  • Центр оценки активов — экспертная функция оценки и доказательной базы.
  • Аналитический центр — аналитика, мониторинг и управленческие выводы.

Центры не считаются отдельными юридическими лицами без документального подтверждения.

РАЗДЕЛЕНИЕ ЦИФРОВЫХ СИСТЕМ

Три независимых контура

  • USERDIE Digital — процессы фонда и операционные данные.
  • BFU — отдельный финансово-токенизированный контур.
  • ZHAKIN Points — отдельный контур баллов и учёта.

Запрещено объединять их балансы, реестры и права доступа по умолчанию.

ПЕРСОНАЛЬНЫЕ ДАННЫЕ

Минимизация и изоляция

  • Собирать только сведения, необходимые для конкретной цели.
  • Разделять идентифицирующие сведения и рабочие данные кейса.
  • Не хранить документы, персональные данные, ключи и секреты в публичном GitHub.

ЧЕЛОВЕК В КОНТУРЕ

Решения остаются за уполномоченными лицами

  • ИИ может классифицировать, проверять комплектность и готовить проекты.
  • Юридические, финансовые и социальные решения утверждает человек.
  • Переводы, начисления и изменение прав требуют отдельного подтверждения.

03 / RBAC И ОБЛАСТЬ ДОСТУПА

Роли не означают доступ ко всему.

Доступ определяется одновременно ролью, назначением, организационным контуром и конкретным объектом.

РольДопустимые действияНе предоставляется автоматически
Руководство фондаУтверждение решений в пределах полномочий, обзор показателей, назначение ответственныхТехнические секреты, закрытые ключи, неограниченный экспорт данных
КоординаторМаршрутизация, контроль сроков, назначение исполнителейИзменение правовых оснований и финансовые операции

Эксперт по активамПодготовка оценки и доказательной базы по назначенным активамУтверждение собственной оценки без независимой проверки
АналитикАгрегированные показатели, отчёты и разрешённые выборкиПрямой доступ к идентифицирующим данным без обоснованной необходимости

Любое разрешение должно иметь владельца, основание, область действия и срок пересмотра. Привилегированные операции требуют усиленной аутентификации и отдельного подтверждения.

04 / API И СЕРВЕРНЫЕ ГРАНИЦЫ

Единый шлюз. Проверяемые операции.

Интерфейс не обращается напрямую к базе и не содержит секретов. Каждая операция проходит серверную проверку полномочий.

Базовые доменные API

  • /api/v1/requests — обращения и дела.
  • /api/v1/programs — программы и проекты.
  • /api/v1/partners — партнёры и гранты доступа.
  • /api/v1/assets — активы, оценки и рецензии.
  • /api/v1/access — роли и назначения.
  • /api/v1/audit — контролируемый просмотр событий.

Обязательные свойства запросов

  • Аутентификация и проверка полномочий на сервере.
  • Валидация схемы и допустимых переходов статуса.
  • Идемпотентность для повторяемых команд и интеграций.
  • Ограничение частоты, размера и объёма выгрузок.
  • Корреляционный ID и журнал результата операции.
  • Единая обработка ошибок без раскрытия внутренних деталей.
Команда → API Gateway → Authentication
                    → Authorization (RBAC + scope)
                    → Domain Service → Data Store
                                  ↘ Audit Event
                                  ↘ Human Approval
                                  ↘ Monitoring / Alerts

Перечень маршрутов — проектный контракт, а не действующие endpoint. Реализация требует отдельного backend, схем OpenAPI, тестов доступа и согласованной модели размещения данных.

05 / SECURITY & PRIVACY BY DESIGN

Контроль до первой реальной записи.

Безопасность — критерий допуска к запуску, а не дополнительная функция после внедрения.

Правовое основание

Определить цели, категории данных, сроки хранения, основания обработки, порядок доступа и удаления.

Защита доступа

SSO или надёжная аутентификация, MFA для привилегированных ролей, RBAC, секреты вне репозитория.

Шифрование

Защищённый транспорт, шифрование хранилищ и резервных копий, управление ключами и ротация.

Журналирование

Аудит чтения и изменения чувствительных объектов, административных действий и экспорта.

Устойчивость

Резервное копирование, проверяемое восстановление, мониторинг, план реагирования на инциденты.

Проверка перед пилотом

Тесты изоляции ролей, негативные сценарии, анализ уязвимостей и ограниченный пилот без избыточных данных.
